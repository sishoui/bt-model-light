# ADR-0029: 配置下发时效——MTU 自适应分片 + 离散动作立即下发

- 状态: 已接受
- 日期: 2026-11-25
- 标签: 小程序, 固件, 协议
- 相关: ADR-0005（二进制 TLV 帧）, ADR-0006（重组，无应用层 ACK）, ADR-0012（测试分层）, ADR-0028（引脚灯带开关）

## 背景

拨一下引脚灯带开关，灯带要 ~2s 才灭。拆开看是三段叠加：

| 段 | 位置 | 实测量级 |
|---|---|---|
| 500ms 防抖 | `autoSync.schedule`（为输入框/滑块连续编辑合并而设） | 0.5s（固定） |
| 空口传输 | 写特征 `PROPERTY_WRITE`（带响应）+ 固定 20 字节/包 | 1.1–1.8s |
| 固件落盘 | `handle_write_config` 内同步 `configPersistSave`（spiffs） | 0.1–0.3s |

第二段是大头：Arduino-ESP32 默认 local MTU 23（框架 `BLEDevice.cpp` 的 `m_localMTU = 23`），小程序侧也从没调 `wx.setBLEMTU`，双方都停在 20 字节/包。写特征又只有 `PROPERTY_WRITE`（带响应），每包要等一个 ATT 响应（一个连接间隔，安卓约 30–50ms）。700 字节的配置 → 36 包 → 1s 以上。

开关是"整份配置重发"的语义（`deviceCard` 的引脚开关改的是 `WRITE_CONFIG` 负载，ADR-0028），所以每拨一次都要走完整传输。

## 决策

### 1. 分片上限按协商 MTU 自适应（两端）

- **固件**：`BLEDevice::setMTU(517)`（框架上限）。local MTU 决定协商上限。
- **小程序**：
  - 安卓：`wx.setBLEMTU({ mtu: 512 })`（该 API 上限）→ 协商成功即用 **509 字节/包**（MTU−3）；
  - iOS / 无该 API / 协商失败：系统自动请求 MTU 185，先用 **182 字节/包** 的乐观值；
  - **首片被平台拒**（说明实际 MTU 没到乐观值，如固件是旧版）→ 整帧退回 **20 字节/包**（`WRITE_CHUNK`）重发，并在本次连接内固定该上限；
  - 分片上限在 `connect()` 时定一次，`disconnect()` 复位。
- **只在首片失败时降级**：首片失败意味着空口一个字节都没发出去，整帧重发不会在固件流式解析器里留半截帧；中途失败不重发（半截帧 + 重发会交错污染字节流，交给 autoSync 的既有重试）。

### 2. 离散动作跳过防抖

`autoSync.schedule(deviceId, config, { immediate: true })`：引脚开关这类"点一下"的动作立即下发，不再等 500ms 合并窗口。输入框/滑块等连续编辑保持防抖。

## 理由

- **收益大、协议不变**：700 字节配置从 36 包降到 2 包，加上跳防抖，端到端从 ~2s 降到 ~200ms 量级；帧格式、配置 blob、命令集全不动。
- **双向兼容**：新小程序 + 旧固件 → 首片被拒自动退回 20B（与今天一致）；旧小程序 + 新固件 → 旧小程序本来就 20B/包，不受影响。
- **重同步天然安全**：分片只是传输层切分，固件按字节流重组（ADR-0006），任意分包方式都成立；自适应用的也是这个性质。
- **不引入新命令**：不做"只发改动字段"的增量命令（那要动协议与固件状态机），先用 MTU 把整份配置的传输成本压到可忽略。

## 影响

- `miniprogram/utils/bleClient.js`：`_negotiateMtu()` + 自适应分片 + 首片降级；新增只读 `chunk`（当前分片上限，便于排障/测试）。
- `miniprogram/utils/autoSync.js`：`schedule(..., { immediate })`。
- `miniprogram/pages/home/home.js`、`pages/pin-detail/pin-detail.js`：两个灯带开关入口传 `{ immediate: true }`。
- `firmware/src/ble_service.cpp`：BLE 初始化后 `BLEDevice::setMTU(517)`（RAM 代价可忽略，占用约 0.5KB/连接）。
- `protocol/frame-spec.md`「单帧长度与 MTU」：写明自适应分片的三档口径。
- `docs/smoke-test.md`：空口章节新增"分片自适应""大配置跨包重组""旧固件兼容"三项真机检查。

## 备选

- **只跳防抖（不改 MTU）**：省 0.5s，仍剩 1.1–1.8s 传输，收益不足，被否为"唯一方案"（可作为降级路径保留）。
- **写特征加 `PROPERTY_WRITE_NR`（无响应写）**：可一连接事件连发多包，但微信侧写类型不完全可控（各平台/版本行为不一致），且 MTU 提上去后 2 包已够快，收益边际，暂不做。
- **固件把 spiffs 落盘移出命令路径**：省 0.1–0.3s，但把"下发成功即持久化"的保证换成异步窗口（ADR-0014 取舍），收益不值，暂不做。
- **新增"只改引脚开关"的命令**（几字节负载，秒灭）：语义最省，但要动协议表 + 固件状态机 + 双端联调；MTU 方案已经把整份配置压到 2 包，先不做。
- **探针写测 MTU**（先写一包大字节看是否被拒）：效果等同首片降级，但会在空口留下噪声、污染测试里的字节流断言，被否。
