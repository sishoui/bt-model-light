# ADR-0023: 小程序状态管理（页面级 data + 保存按钮）

- 状态: **"保存按钮"部分已被实现取代**（改为"修改即推送"，commit `5cad7b6`）；"页面级 `data`、不引入状态库"部分仍有效
- 日期: 2026-11-23
- 标签: 小程序

## 背景

小程序编辑中的配置如何管理？编辑即存、编辑态+保存、引入 mobx/redux。

## 决策

> 现状（2026-11-26）：保存按钮已移除（commit `5cad7b6`），改为**修改即推送**——编辑直接写 Storage 并经 `autoSync` 500ms 防抖下发（`WRITE_CONFIG` + `APPLY`），页面顶部同步状态条显示 `同步中 / 已同步 / 仅本机 / 同步失败`；离开拦截只在同步在途时触发。ADR-0028/0029/0030 均按此实现引用 `autoSync`。本次反转当时未单独出 ADR，需要正式记录时补一条。
>
> 以下为 2026-11-23 的原决策，保留作记录。

采用 **页面级 `data` + "保存"按钮**：

- 编辑态与已保存态分离，避免误操作立即写固件
- "保存"按钮同时写 Storage + 下发固件
- 页面级 `data` 够用，不引入状态库

## 理由

- 编辑态与已保存态分离，语义清晰
- 灯组配置是结构化数据，页面级 `data` 足够
- 不引入 mobx/redux，保持轻量

## 影响

- 灯组编辑页（现为"引脚配置详情页"的灯组 Tab 内）`data` 含：`ledRange`、`steps[]`、`layers[]`、`dirty` 标志
- "保存"按钮：写 `wx.setStorageSync('device_config_<id>', config)` + 下发 `WRITE_CONFIG` + `APPLY`
- 编辑中切换页面提示"未保存"
- 跨页面共享状态（如首页整体开关、当前选中设备）用 `getApp()` 全局或 Storage，见 ADR-0027

## 备选

- 编辑即存 Storage：误操作立即写固件，风险
- 引入状态库：对单页编辑过度
