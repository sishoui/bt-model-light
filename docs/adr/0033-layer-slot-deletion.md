# ADR-0033: 图层固定双槽 + 可删空（不升协议版本）

- 状态: 已接受
- 日期: 2026-11-26
- 标签: 小程序, 协议, 文档

## 背景

需求：图层卡片右上角要能单独删除 — 可以删背景层，也可以删动效层；删掉之后剩下的图层**留在原位**；两格都删完则灯珠不亮。

现状冲突：`protocol/frame-spec.md` 规定 `layer_count` 为 **1~2**，固件 `config_validate` 与小程序 `configCodec.validateConfig` 都拒绝 0，固件测试 `test_validate_layer_count_zero` 明确断言 0 必须回 `0x03 配置超限`。也就是说"零图层"在 wire 格式里不是合法形态。

## 决策

**1. 图层由"顺序"改为"固定槽位"（小程序侧模型）**

每阶段的 `layers` 恒为两项，`slot` 0 = 背景、1 = 动效。空槽用占位对象（`empty: true`、`effect: null`）表示，保留在数组里让两格位置固定：

- 删掉背景 → 槽 0 变占位，动效留在槽 1，符合"剩下图层留在原位"。
- 删掉动效 → 槽 1 变占位，背景不动。
- 两格都空 → 该阶段无图层。

存储与 wire 模型带 `slot` 字段，重进页面按槽位落格（旧配置无 `slot` 时按数组序 0/1 推断）。

**2. 零图层在 wire 上兜底成"单层全黑 SOLID"**

固件要求 `layer_count ≥ 1`，但渲染单层时直接取该层输出。所以 `encodeConfigBlob` 在两槽都空时下发一层 `SOLID` 且 `color=000`、`brightness=0`——输出全黑，与"无图层"的显示结果完全一致。

**3. 不改协议版本、不改固件**

`layer_count` 语义仍是 1~2，固件与小程序的编解码、校验、合成逻辑一行不动。好处：

- 按 ADR-0009，协议 minor 变更会让已刷固件被小程序判为不兼容并阻断下发；本方案让现网 1.2 固件继续可用，不需要重新刷机。
- 零图层的语义落在 App 层，固件永远只看到合法配置。

## 理由

- **需求本质是 UI 的表达自由，不是设备新能力**。设备只需要"亮"和"不亮"，而"不亮"已能用全黑单层表达。
- 固定槽位让"删背景后动效留在第二格"这种位置语义在重进页面、跨设备同步后都稳定；顺序模型做不到（删掉第 0 项后动效会顶上来变成第 0 项）。
- 避免协议升版带来的连锁成本（固件重新验证、OTA 流程、兼容矩阵、真机回归）。

## 影响

- 小程序：`pin-detail` 图层 VM 固定两项（含空占位）；`configCodec.validateConfig` 允许 `layers.length === 0`；`encodeConfigBlob` 做全黑兜底；`vmToGroup` 跳过空槽并带上 `slot`；timeline 跳过空槽。
- 固件：**无改动**。
- 协议：**无改动**（`layer_count` 仍为 1~2）。§约束补一条说明：小程序用"单层全黑"表达该阶段不亮。
- 兼容性：旧配置（无 `slot`）按数组序落格，行为与之前一致。

## 备选

- **协议放开 `layer_count` 到 0~2**：语义最干净，固件 `composition.cpp` 已有 `layer_count == 0 → 返回黑色` 分支。但需要 bump 协议 minor，现网固件会被判不兼容、必须重刷，代价与收益不匹配。
- **图层加 slot 字节上协议**：与上一条同样的升版代价，且固件要新增字段解析与合成分支；当前只有两槽，App 层足以表达。
- **保持顺序模型、允许删到 0**：实现最省，但"剩下的图层留在原位"做不到——删掉背景后动效会顶到第一格，位置语义丢失。
