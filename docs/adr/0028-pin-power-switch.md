# ADR-0028: 引脚灯带开关（pin.power）语义

- 状态: 已接受
- 日期: 2026-11-25
- 标签: 小程序, 固件, 文档
- 相关: ADR-0007（命令集）, ADR-0020（合成/渲染）, ADR-0023（小程序状态）, ADR-0027（页面结构）

## 背景

ADR-0027 给首页引脚卡片和引脚详情页顶部都安排了"引脚灯光开关"，配置模型里对应 `pin.power`。但实现时它只写进 Storage 与页面 data：协议 blob（`protocol/frame-spec.md`「配置负载」）没有对应字段，固件 `config.cpp` / `composition.cpp` 也不读它。结果是开关拨了、灯带不灭——**失效开关**。

两条路可选：

1. 给引脚块加一个 `power` 字节：语义最直白（固件能区分"关机"与"未配置"），但要改 frame-spec、固件编解码、渲染分支、Unity 测试，还要重烧固件并处理新旧版本兼容。
2. 复用固件已有的"该引脚无灯组"语义：`group_count = 0` 时渲染路径先清黑整条灯带、再无灯组可画，等价于该灯带熄灭。

## 决策

**关（`pin.power === false`）= 编码 `WRITE_CONFIG` 时该引脚 `group_count = 0`，不下发任何灯组。开 = 正常下发该引脚的灯组。**

- 只有显式 `false` 才算关；字段缺失（老配置）视为开，保持"配好就亮"，避免存量配置切页后被误灭。
- 开关是**设备配置的一部分**（`device_config_<id>` 的 `pin.power`），与灯组同源同生命周期：改动 → 落盘 Storage → `autoSync` 防抖下发（`WRITE_CONFIG` + `APPLY`），与 pin-detail 其它改动同一条链路（ADR-0023 / ADR-0027）。
- 首页引脚卡片开关与引脚详情页顶部开关是**同一字段的两个入口**，各自从 Storage 读，不引入第二份状态。
- 关灯**不删配置**：灯组（灯珠区间 / 阶段 / 图层 / 灯效参数）在 Storage 里完整保留，重新打开即恢复原样。

## 理由

- **零协议改动**：帧格式、blob 布局、`CONFIG_VERSION` 全不变，固件不用重烧，新旧固件/小程序之间不会出现版本不兼容。
- **固件已有语义**：`group_count = 0` 本就是"该引脚未配置"，`composition_render_all` 对无灯组的引脚照样走清黑路径，不需要新增状态位或渲染分支。
- **单一推送链路**：复用"配置即推送"（Storage 真相源 → autoSync → WRITE_CONFIG + APPLY），不为电源另开一套命令。
- **断电保留**：固件 spiffs 存的就是这份 blob，关灯状态随配置一起持久化，重启后仍然灭。

## 影响

- `miniprogram/utils/configCodec.js`：`encodeConfigBlob` 按 `pin.power` 决定该引脚是否下发灯组。
- `miniprogram/pages/home/home.js`：引脚卡片开关接 `onPinPowerChange`（校验 → 落盘 → `autoSync.schedule` → 刷新卡片）。
- `miniprogram/pages/pin-detail/pin-detail.js`：顶部开关默认值改为"未显式关闭 = 开"，与卡片同口径；首次配置保存即写入默认开。
- **固件 READ_CONFIG 回读时，关闭的引脚表现为"无灯组"**（`config_decode` 跳过 `group_count = 0` 的引脚，不进模型）。小程序目前不以 READ_CONFIG 为真相源；将来若接入，需要以 Storage 为准合并，不能把回读结果直接当配置。
- 设备卡片上的"整体开关"（一键控制所有引脚）：先按 ADR-0031 实现为扇出到本 ADR 的 `pin.power`，真机试用后由 **ADR-0032** 改为**设备级总开关**（`SET_POWER`，不改引脚状态；关机时引脚区置灰不可操作）——本 ADR 的引脚开关语义不变。

## 备选

- **引脚块加 `power` 字节**：固件能区分"关机"与"未配置"，为将来的低功耗 / 状态回传留位置；但要动协议 + 固件 + 重烧 + 版本兼容，当前收益不抵成本。若日后固件侧确实需要这个区分，按 ADR-0007 走新增命令或升 `CONFIG_VERSION`。
- **只保存 `pin.power`、不改编码**：开关在物理层面依然失效，等于把"点了没反应"换成"点了没物理效果"，被否。
- **用 `STOP`(0x06) 表示关灯**：`STOP` 的语义是"停止播放，保持当前亮灯"，且是全局命令、无引脚粒度，被否。
- **关闭时把灯组灯珠区间改成 255 空组哨兵**：也能灭灯，但会把"空组"与"关灯"两种含义混在一个字段里，且固件回读时看到的是空组而非无灯组，语义更含糊，被否。
