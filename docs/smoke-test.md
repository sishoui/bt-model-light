# 真机 Smoke Test 清单（Android）

> 发布前在 **1 台代表 Android 设备** 上跑一遍。Smoke test 覆盖 Mock 无法替代的**物理正确性**：空口 MTU/分包、notify 时序、系统蓝牙/权限路径、真实硬件响应（ADR-0012 / GLOSSARY「Smoke test」）。问题与排查记录回填到本 issue。

## 前置条件

- [ ] 固件已烧录到 ESP32-C3（`firmware/`，`pio run -e esp32-c3-devkitm-1 -t upload`），串口日志可见（115200）。
- [ ] WS2812B 灯带按 8 引脚接线完成，供电正常。
- [ ] 测试机已安装微信，登录可用账号（当前账号「死守i」）。
- [ ] 小程序已用「真机调试」或体验版打开（**开发者工具不算发布前 QA**，仅可用于链路层初筛）。
- [ ] 准备一台 BLE Sniffer（nRF Sniffer / Ellisys 等）——仅在排障分包/重传问题时使用。
- [ ] 记录测试机的 **Android 厂商 / 系统版本 / 微信版本**（版本矩阵是兼容性验证维度，见 `arena-feasibility/final-report.md` 第三节第 4 条）。

## 一、权限路径（Android 必测）

- [ ] **Android 12+**：首次扫描触发 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` 运行时权限弹窗 → 允许 → 可扫描。
- [ ] **Android 12+**：扫描权限拒绝 → 友好提示（引导去设置授予「附近的设备」权限），不崩溃。
- [ ] **Android ≤11**：需**定位权限** + **定位服务开启**才能扫描 BLE → 关闭定位 → 友好提示。
- [ ] 系统蓝牙关闭（扫描/connect 返回 `errCode 10001`）→ 友好提示。
- [ ] 真机确认扫描/连接无「接口调用失败：未授权/未声明」类错误（若 `app.json` 需补 `scope.bluetooth`/定位说明，按真机报错补齐后重试）。

> 微信对 errCode/errMsg 文案随平台与基础库版本有差异，`errorHandler.js` 的 `WX_MESSAGES` 仅覆盖常见码，其余走兜底文案——记录实际 errMsg 以便补映射。

## 二、端到端主流程（happy path）

- [ ] 打开小程序 → 「设备」Tab 默认首页，未连接时显示「未连接设备」。
- [ ] 左上设备名 → 设备列表 → 「新增设备」→ 扫描到 `BTLight_` 前缀设备（非前缀设备不出现）。
- [ ] 同一设备多次广播时列表去重，RSSI 取较优值（信号强度合理）。
- [ ] 点选设备 → 连接成功 → 自动 `GET_VERSION` 协商 → 返回首页，`connected=true`，显示设备名。
- [ ] 设备已保存：杀进程重进 → 设备仍在列表，可一键切换。
- [ ] 进入引脚配置详情页 → 选灯珠区间 → 选灯效（8 种逐一验证灯珠实际表现）→ **修改即自动同步**（顶部状态条「同步中…」→「已同步」）→ **灯珠实时响应**（WRITE_CONFIG + APPLY 下发成功，无保存按钮）。
- [ ] 自动同步：连续快速改动只触发一次下发（防抖合并）；断连时改动落盘本机（状态条「仅本机」），重新连接后自动补发（状态条「已同步」）。
- [ ] 步骤/图层：多步骤、双图层合成（动效层非黑优先）在灯带上表现正确。
- [ ] 图层槽位删除（ADR-0033）：卡片右上角 ✕ 可单独删背景层或动效层；删掉背景后动效层仍在第二格（重进页面、切组返回后位置不变）；只留动效层时灯带按该动效正常播放。
- [ ] 两格都删空：阶段下方出现「本阶段没有图层，灯珠不亮」，下发后该灯组**整条灭**（不是残留上一帧）。
- [ ] 空槽添加：点空槽卡片就地新建（不弹配置弹窗），创建后可点开继续改灯效/参数。
- [ ] 校验边界：灯珠区间/灯组数/步骤数/图层数超限时给友好 Toast，不下发、不崩溃。
- [ ] 整机开关（ADR-0032）：设备图「关机」→ 8 条灯带**全部灭**，但**各引脚的开关状态不变**（卡片开关仍显示原来的开/关）；「开机」→ 灯带按各引脚原状态恢复（之前单独关掉的引脚仍是灭）。
- [ ] 整机关机时引脚区不可操作（ADR-0032）：引脚卡片灰化（半透明/去色）、点击不进配置页、卡片上的灯带开关点了不动（disabled）；再次开机后全部恢复可操作。
- [ ] 进引脚配置详情页时设备处于关机状态 → 顶部「灯带开关」同样置灰不可切换（并等待重连补发）。
- [ ] 整机亮度（ADR-0031）：点左下角亮度**方块** → 展开成竖长条并居中到屏幕中部（有过渡动画，不闪跳）→ **上下滑动** → 8 条灯带同步变亮/变暗，滑动过程中连续跟随（不只在松手后跳一次）；上滑变亮、下滑变暗；松手后数值落盘，切页/杀进程回来不丢。
- [ ] 亮度竖条收起：点**其他任意位置** → 长条收回成方块；点竖条本身不会误收起（仍能拖动）；收起不重置亮度。
- [ ] 收起态比例：调到 30% 后收起 → 方块内部填充仍是 30% 高度（不是满格也不是空）；调到 0% 收起时方块几乎全空。
- [ ] 收起态不误调光：**未展开**时在方块上横向/纵向滑动 → 亮度不变、页面正常滚动（方块只是入口）。
- [ ] 展开态不受裁切：竖条完整显示，**不被舞台 `overflow: hidden` 切头尾**；收起后右侧「关机/开机」按钮位置没有跳动（槽位占位生效）。
- [ ] 整体亮度边界：滑到 0 → 全黑不崩不花屏、竖条读到空（不弹回 255）；255 = 不缩放（与图层参数里的亮度相乘）、竖条满格。
- [ ] 无底板可读性：换一张浅色（白的）设备图 → 方块里的数值、「关机」都还看得清；删掉设备图后（空态白底）方块是浅灰底、数值是深色。
- [ ] 整机状态断连补发：未连接时改亮度/开关机 → 状态条「仅本机」不报错；重连后自动补发（先开关后亮度），灯珠按该状态渲染。

## 三、空口 / 时序（MTU 与分包，真机独有）

- [ ] 分片自适应（ADR-0029）：安卓协商到 509 字节/包、iOS 182 字节/包；整份配置 2~4 包发完（日志可见 `[bleClient]` 无"分片被平台拒"警告）。
- [ ] 大配置（接近单帧上限，>509 字节）下发时跨包重组成功（固件正确回 OK/STATE，无 CRC 错误 Toast）。
- [ ] 旧固件兼容：连一台 local MTU 仍为 23 的设备 → 首片被拒后自动退回 20 字节/包，配置照样下发成功。
- [ ] 连续快速下发多条命令无丢帧/错序（seq 回显对得上）。
- [ ] notify 回传（STATE/OK/ERROR/VERSION）在真机时序下被正确解析（不依赖单包整帧）。
- [ ] 拨引脚灯带开关：灯带立即灭/立即恢复，**灭灯前不闪出厂彩虹**（CONFIGURED 保持上一帧，ADR-0030）。
- [ ] 落盘不阻塞命令路径（ADR-0030）：连续快速拨开关，每次 WRITE_CONFIG 的 OK 都立即回，无逐次变慢。
- [ ] 整机命令不重发配置（ADR-0031/0032）：连续滑动亮度竖条只发 `SET_BRIGHTNESS`、点开关机只发 `SET_POWER`（各 1 字节负载，抓包可见），不发 WRITE_CONFIG，灯珠连续跟随无卡顿。
- [ ] （排障时）BLE Sniffer 确认分包与重传符合 frame-spec.md，无半帧误判。

## 四、异常与生命周期

- [ ] 连接中断电/重启设备 → 小程序 `onBLEConnectionStateChange` 收到断开 → `connected=false`，重连后恢复。
- [ ] 小程序切后台再回前台 → 连接状态与页面一致（不串状态）。
- [ ] 设备列表长按删除设备 → 二次确认 → 设备与配置清除。
- [ ] 引脚配置页同步在途（状态条「同步中…」）时返回 → 触发离开拦截（`enableAlertBeforeUnload`）；「已同步/仅本机」状态返回不拦截。
- [ ] 同步失败（状态条「同步失败，点此重试」）→ 点击立即重发；重试成功转「已同步」。
- [ ] 固件回 ERROR（如未配置时 APPLY → `0x05`）→ 小程序友好提示 + 本地日志 `error_log` 记录。
- [ ] 协议版本不兼容（固件主版本不符）→ Modal 提示升级，不下发命令。
- [ ] 长按 BOOT 键 5 秒 → 恢复出厂默认（呼吸彩光），重启后生效。
- [ ] 长按 BOOT 5 秒复位后整机亮度回满（ADR-0031）：复位前调到较暗，复位后灯不再保持暗度；随后 App 重连会按本地记录补发一次亮度。
- [ ] 掉电保留（ADR-0014 + 0030 窗口）：改动后**等 1 秒**再断电重启 → 改动保留；改动后**立刻**断电重启 → 允许丢这一次改动（回落 spiffs 上一份或出厂默认，不崩、不花屏）。
- [ ] 复位干净（ADR-0030）：长按 BOOT 复位后立刻断电重启 → 不会把复位前的配置写回 spiffs（仍是出厂默认）。

## 五、固件版本与 BLE OTA（ADR-0034）

> OTA 只能真机验证：下载走小程序网络栈、写入走空口、切分区与回滚在 bootloader 里完成。
> 自动测试只覆盖「帧序列 / offset 连续 / CRC 计算 / 版本比较」。

**前置**：设备已数据线烧录 **≥0.4** 固件（现网 0.3 无 OTA 能力，必须先有线刷一次）；
服务器已 `publish` 且 `firmware_release.py verify` 通过。

- [ ] 连接设备 → 首页左上角显示 `已连接` 与固件版本 `v0.4`（连接即上报，不依赖 GET_VERSION 回包）。
- [ ] 杀进程重进小程序（未自动连上）→ 首页仍显示上次已知版本（不出现空白）。
- [ ] 「我的」页「固件升级」行显示当前版本；未连接时显示"未连接"。
- [ ] 服务器版本等于设备版本 → 点「固件升级」弹"已是最新"，无"升级"按钮。
- [ ] 服务器版本更新 → 弹"发现新固件 + 版本差异 + 大小"，确认后进入进度弹层。
- [ ] 升级中进度条随写入增长（**不是卡 0% 再突然完成**）；灯带不断电、不闪花。
- [ ] 完成后约 0.3s 设备重启：小程序自动断开 → 自动重连 → 版本号变为新版本（无需杀进程）。
- [ ] 升级后**配置不丢**（spiffs 与 ota 分区分离，ADR-0010/0014）：灯效、整机亮度/开关一致。
- [ ] 升级中关闭手机蓝牙 → 中止并提示失败；设备仍跑旧固件、灯效正常；重连后可再升级。
- [ ] 升级中切 App 到后台 → 继续完成或失败可控；不出现"半新半旧"。
- [ ] **回滚**：发布一版 `setup()` 故意崩溃的镜像 → 升级后自动回滚旧版（版本号仍旧），灯带正常。
- [ ] 升级中拔电 → 重新上电进旧固件、灯效正常、可再发起升级。
- [ ] 空口分片 < 64（如 local MTU 仍 23）→ 提示"分片太小不可升级"，不发 BEGIN。
- [ ] 协议不兼容的设备**仍允许发起 OTA**（自救通道，ADR-0034 §2）；其它命令依旧被拦截。

## 六、本地日志核对

- [ ] 制造一次错误后，确认 `error_log`（Storage）新增一条（含 context / code / message / ts）。
- [ ] 用户配置页清除本地数据 → 设备/配置/日志清空。

## 七、用户配置页与云端同步（ADR-0035，需人工）

前置：`python scripts/backend_deploy.py verify` 五项全绿；手机微信与开发者工具同账号。

- [ ] 底部第二 Tab 进入「我的」→ 顶部账号卡显示「未登录 / 微信登录」按钮（文案不是空）。
- [ ] 未登录时连 BLE 一切照旧（首页开关、引脚配置、下发）→ 云端同步行显示「未登录（仅本机）」。
- [ ] 点「微信登录」→ 微信授权 → 账号卡显示昵称（未设置昵称时为空输入框）+「退出登录」。
- [ ] 点头像（`open-type="chooseAvatar"`）→ 选图 → 提示「头像已更新」，重启小程序仍在。
- [ ] 改昵称 → 失焦即提示「昵称已更新」；杀掉进程重进仍是新昵称。
- [ ] 首页长按设备卡片改名 → 用户配置页「云端同步」点一下 → 显示「已同步」。
- [ ] 换另一台手机 / 清小程序缓存后重装 → 登录 → 设备清单自动补回（名称一致）。
- [ ] 后台（`/admin/`）用户列表能看到该用户与设备数（`deviceCount` 与实际一致）。
- [ ] 后台停用该用户 → 手机端下一次请求返回 401（页面回到未登录态），不是白屏/死循环。
- [ ] 断网（飞行模式）点「云端同步」→ 提示可读文案（网络不可用…），不崩溃；BLE 仍可用。
- [ ] 退出登录 → 本地设备清单**保留**（只有云端不再同步）。

> 说明：`wx.request` 到 `http://117.72.163.247/api` 属 IP 直连，只在开发者工具与「真机调试」
> 下可用；体验版/正式版会因域名校验失败（ADR-0034 §9 / ADR-0035「已知限制」），
> 这不是 bug，等备案域名 + HTTPS。
